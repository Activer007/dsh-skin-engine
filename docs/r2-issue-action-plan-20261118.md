## 一、范围和开发纪律

本轮聚焦六项问题：版本发布不同步、原创素材声明、人物换图范围固定、用户换图配额无清理入口、特效参数映射分散、近期动效缺少同候选双端完整性能基线。

1. **优先可用与稳定，避免过度设计**。每条 Goal 小步开发、独立 PR、明确回归范围。
2. 保持现有 11 款内置皮肤的 ID、已保存设置、30 秒聊天预览、恢复默认、旧 `.dshskin.zip` 契约可用。
3. **文档确认与技术验收分开**。作者已确认皮肤美术素材为自己创作或使用生成工具独立生成；这一事实按作者确认更新现行说明。代码打包、截图归属、第三方依赖的许可证仍单独处理。
4. 每项任务以实际 `main` 最新状态为基线，不从历史 `v1.5` 任务表推断未完成；只在合入后将相应任务标记为完成。
5. 本文不要求 CI 重构、云同步、在线商店、独立皮肤编辑器或任意第三方脚本执行。

## 三、分项设计与验收

### R2-DOC-01 · 原创素材声明（本次文档 PR）

**确认口径**：项目作者明确确认，Skin Engine 自制皮肤所用的人物插画、壁纸、视觉场景及相关美术元素均为作者自行创作或使用生成工具独立生成，未直接复制其他仓库的美术资源。之前“原作者、再分发授权待确认”的措辞针对这批自制美术素材已不适用。

建议统一说明：

> Skin Engine 内置皮肤及官方样例中的美术素材由项目作者自行创作或使用生成工具独立生成，未直接复制其他项目的美术素材。项目自身代码采用 MIT 许可证。展示截图或视频中的 DeepSeek Harness 界面、名称、标志及项目所使用的第三方依赖，仍遵循其各自的权利归属与许可条款。

**修改位置**：`README.md`、`README.en.md`、`docs/release-asset-notes.md`、`docs/release-assets.json` 的 `provenance` 文案、`skin-sources/LICENSE-NOTES.md`。把本任务书链接至 `docs/development-roadmap.md`。不修改素材字节、Sha256、源路径、生成技术记录或许可证文件。保留 DSH 实际界面截图的来源和第三方组件 Notice。

**验收**：
- 中英文说明一致；旧的原创人物图“未知原作者/再分发授权待确认”不再出现。
- `release-assets.json` 能被解析，`files` 条目、路径、哈希、像素和字节数完全不变。
- 第三方依赖许可和 DSH 界面/标志归属未被改称本项目所有。
- 此项仅更新“已确认的项目来源声明”，不声称完成独立的法律审计。

### R2-REL-01 · 版本与发行收口

**问题**：源码 `package.json` 已为 `1.10.3`，但 `GitHub Releases` 当前最新公开版本仍为 `v1.10.1`。近期 `PR #1 / #2 / #3-#5` 已使实际演示、侧栏动效和极光参数与上一发行版不同。

**任务**：
1. 固定待发候选完整 Git SHA；复核 11 款内置皮肤、`Engine API 1.6`、DSH 兼容范围与文档。「浮光深境 VI」1.2.0 随发行提供独立 `.dshskin.zip`，保留其 ID，把它加入可复现打包与 `SHA256SUMS.txt`，并在中英文 README 写明如何导入。
2. `npm ci`、`npm run build`、`npm run typecheck`、`npm run lint`、`npm test`，然后使用项目既有 `verify:local` / `npm pack` 入口核对可复建 tarball、文件内容和 SHA-256。
3. 真实 DSH Web 与 Windows Desktop 使用**同一份 tarball 和同一份独立 ZIP**验收。覆盖外观中心、侧栏动效、composer、Deep Ocean、Aurora、浮光深境 VI 导入与应用、个人换图、预览/保存/取消/恢复、关闭/卸载、明暗与辅助功能。记录宿主精确版本，优先使用 `0.2.2-rc.3`。
4. 对照 `R2-PERF-01` 补上新组合的性能记录，明确哪些已测、哪些缺证据；不把历史不同候选的测试冒充本版结果。
5. 通过后再创建正式 Release，附引擎安装包、浮光深境 VI ZIP、`SHA256SUMS.txt`、版本说明及更新演示。README 在发布前明确当前可下载的版本。

**验收出口**：产物可复建、与实际安装字节一致；宿主回归有可追溯记录；README 中英文和发布说明一致。发布前不得将未测试项写成通过。

### R2-ART-01 · 用户换图素材管理

**当前问题**：`src/host/user-artwork.ts` 在内容寻址保存目录下限制最多 32 张不同素材；接口只有上传与读取。当前“恢复原图”仅撤销皮肤偏好，不会删除本地旧图片。

**分步实现（先小后大）**：
1. Host 新增受权限保护的素材列表/配额查询，仅针对当前 Profile；显示图片数量、已占字节、名称/缩略图和**持久保存偏好**中的引用状态。
2. UI 在现有“自定义皮肤”或“皮肤管理”中提供“已保存的个人图片”，先让用户看清配额和使用情况，不立即新增自动清理服务。
3. 在 Host 的受控存储锁下提供**明确用户触发**的删除：校验内容哈希文件名、Profile 边界、引用情况，并拒绝删除仍由已保存偏好引用的文件。当前工作窗口的草稿也应阻止删除。
4. **特别注意其他窗口的未保存草稿**：Host 无法凭现有持久偏好识别所有打开窗口的临时草稿。首版不能把“未持久引用”直接宣称为“绝对未使用”，应在删除确认提示其他窗口未保存草稿可能受影响；不设计自动回收。如需无提示安全回收，再单独设计草稿租约/跨窗口引用登记。
5. 删除后返回实际配额，更新界面；配额满时清楚提示可处理哪些素材。保留原上限 32，暂不引入无限存储。

**验收**：最大值、重复图去重、并发上传/删除、外部越界请求、仍被保存偏好引用、删除后的容量释放、预览及重启回读、双窗口草稿提示/防护。删除不能影响 ZIP 内置图片和其他 Profile。

### R2-ART-02 · 声明式换图

**问题**：`portraitSkinIds` 固定六个 ID，新导入的合规人物皮肤不能自动获得相同的替换控件。

**最小设计**：为 `Skin Manifest` 定义**可选**且经 Host 严格验证的 `customizable.artwork` 能力：是否支持用户提供的单张主图、允许的场景位置与默认值。先只开放一张主图；多图、图层蒙版、拖拽画布留给后续版本。

**迁移**：
- 为现有六款皮肤补声明，过渡期保留旧 ID 到默认行为的兼容路径；不能让旧用户升级后失去已保存图片。
- 检查 `src/core/manifest.ts`、`src/shared/user-artwork.ts`、`src/client/artwork-editor.tsx`、`src/client/skin-detail.tsx`、`src/client/skin-switch.ts`、Host 资产验证与 ZIP 作者模板。
- 更新 Engine API 版本仅在协议要求变化时进行，并为旧 ZIP 保留读取规则；外部 ZIP 仍不能执行任意 JS。

**验收**：新样例单图更换、旧六款零迁移损失、无声明皮肤不出现换图入口、非法声明拒绝、窄窗/双明暗/预览取消及重启回读。

### R2-FX-01 · 统一特效参数描述

**问题**：`src/core/effects.ts` 定义 Schema，`src/shared/preferences.ts` 定义强度和参数映射，`src/client/skin-effects.tsx` 重复定义分组、标签和可见滑块。新增参数可能只在一处更新而出现 UI 与运行时不一致。

**设计**：在可信引擎代码中为可编辑参数集中维护 `EffectDescriptor`（ID、控件、单位、范围、默认值、参数映射、分组、兼容版本与降级提示），由 UI 基于描述渲染常规输入；特殊交互允许显式自定义控件。Provider 的生命周期、预算及渲染逻辑不和 UI 描述混为一个巨型模块。

**验收**：现有全套效果参数“旧值读取 → 编辑 → 预览 → 保存 → 重启”逐值一致；边界数值和坏输入受验证；扩展新参数只需局部改动；不得改变已发布 `effects.json`、`preferences` 行为或开放第三方脚本执行。

### R2-PERF-01 · 当前动效真实性能边界

**基线**：`src/client/effects/frame-scheduler.ts` 已是统一时钟；`auto-quality.ts` 依靠帧间隔和 JS 工作耗时降档；`quality.ts` 设定 Low 20、Balanced 30、High 60 FPS 的目标。CSS 滤镜、浏览器合成或 GPU 压力不能仅凭 JS 耗时完整判断。

**测试矩阵**：
- 平台：官方 DSH Web 和 Windows Desktop；精确记录对应宿主版本（优先实际支持的 rc.3），使用相同 tarball。
- 状态：Default、Static、Dynamic Balanced、Dynamic High、Auto；侧栏动效开/关；窗口隐藏/恢复、Reduced Motion、Forced Colors。
- 皮肤：Deep Ocean、Aurora、浮光深境 VI，至少包含实际高密度粒子、极光和液态材质组合。
- 视口：1280、760 CSS px；涉及侧栏抽屉或响应式风险时补 520；记录 DPR=1/2 的真实环境。
- 度量：可信输入和侧栏折展 P95、长任务、实际帧率、Canvas 缓冲与数量、RAF、堆变化、GPU 上下文创建/释放、持续 300 秒隐藏后的资源归零和恢复。
- 先沿用文档的 **16.7ms P95 增量排查线**进行归因，不把这条排查线误写成任意场景的硬性承诺；基线抖动大时使用顺序交叉的成对实验。
- 遇到真正回归再单独修复；优先隔离 CSS 合成、侧栏滤镜、Canvas 粒子与宿主同步布局成本，不预先宣布某一项为瓶颈。

**验收**：报告绑定 Git SHA、tarball SHA256、Host 版本、环境、精确开关、原始结果和异常；对未测组合明确标注“未验证”。自动质量与静态回退不能误影响输入功能。

## 五、可直接用于 Codex Goal 的任务提示词

### Goal A：发布可靠性
> 以最新 main 为准，先只审查 DSH Skin Engine 1.10.3 的发行闭环和真实 Web/Windows 宿主证据。按 docs/r2-issue-action-plan-20261118.md 的 R2-REL-01 / R2-PERF-01 执行。固定 SHA 和同一 tarball；明确未测项；仅修复验证中实际发现的问题。不要扩大到新特效、独立编辑器或 CI 重构。

### Goal B：用户素材管理
> 依据 R2-ART-01，小步增加本地用户换图图片的可视配额与安全删除。确认持久偏好引用和多窗口草稿的局限，禁止静默自动删除。保持原有内容哈希、32 图上限、Profile 隔离和现有恢复语义；增加恶意输入、并发、回读的测试；先设计再修改代码，提交独立 PR。

### Goal C：声明式换图
> 依据 R2-ART-02，将固定六款人物皮肤的换图判断逐渐迁移为 Manifest 声明。首版仅支持单张主图，旧包、旧偏好、旧六款 ID 全部兼容。不要开发自由排版编辑器或允许第三方脚本；新增作者示例与 Host/Client 双端验收。

### Goal D：特效元数据
> 依据 R2-FX-01，在可信引擎内部建立统一 EffectDescriptor，减少 Schema/偏好映射/UI 的重复维护。先对现有参数做兼容性回归，旧 JSON 与已保存强度必须逐值一致。不要顺便增加新效果，也不调整 Provider 的安全边界。
