# 本地皮肤包更新与回滚

PR-18 定义本地包契约和两版验收夹具。PR-22 实现写入、界面和故障恢复。引擎 tarball 的升级与回滚继续走 DSH 插件管理。 [开发路线图](development-roadmap.md#后续任务) · [引擎回滚](release-v1.md#回滚)

## 更新资格

- 只允许更新当前 profile 通过 ZIP 安装的本地皮肤。内置皮肤和仅从目录发现的皮肤保持现有管理方式。选择皮肤后从独立更新入口上传 ZIP。普通导入仍对重复 ID 返回 `409 duplicate-id`，包括原版本与较新版本。
- 更新包必须使用相同的 `skinId`，且按现有 SemVer 解析器比较，版本优先级严格更高。构建元数据不改变优先级，等价版本与降级均拒绝。预发布版本按 SemVer 优先级比较。引擎和宿主兼容性、ZIP 配额、Manifest、Tokens、Effects、CSS、资源及随包偏好均走生产校验。
- 更新目标在开始上传时绑定到皮肤 ID 与当前包修订号。继续使用 owner 路由和分块上传。完成暂存校验后，在同一 profile 写锁内读取最新目录并重查 ID、版本、兼容性和修订号。新导入、更新、回滚、卸载和保存选择共享该锁。竞争失败返回冲突并要求刷新。

## 提交点与恢复

1. 将完整且已校验的目录移入当前安装目录下的独立版本子目录，保留旧包完整内容。沿用同卷暂存及现有路径、普通文件和链接防护。版本目录以引擎生成的名称定位。
2. 原子替换安装目录内的版本记录。记录包含格式版本、当前与上一版目录标识和每次提交生成的新代次。缺少记录时以原安装目录为当前版，直接兼容现有安装。目录扫描以记录指向的完整包为准，上一版和未引用目录不出现在画廊。记录损坏或指向不可读版本时报告目录问题。
3. 原子替换是唯一提交点。成功后返回新版本和包修订号。修订号纳入提交代次，回滚到相同内容时也发放新修订号。读请求按一次解析到的版本取文件，跨提交的旧请求可完成旧版读取，或在版本已清理时失败并刷新。保存、更新、卸载及回滚都重新核对当前修订号。
4. 提交前取消、校验失败或写入失败保留旧记录与旧包。原子替换报错时持锁重读记录，判断提交是否已经发生。读回结果不确定时保留相关版本，报告操作状态待刷新。进程中断后以磁盘记录判断当前版本，回收未引用的完整目录和废弃暂存。回收按可验证的目录标识在同一把锁内进行，失败可重试。提交后取消或响应丢失时，客户端刷新目录确认结果。

回滚需要当前包修订号和仍可验证的上一版。沿用同一提交点切换回旧目录并清空回滚记录。下一次成功更新重新生成一条回滚记录。每个安装仅有一个可回滚版本。兼容现有安装所需的初始根目录内容可保留到卸载。卸载移动整个安装目录，当前版和回滚版一同清理。

## 活动皮肤与偏好

- 选择和偏好继续按 `skinId` 保存，包更新及回滚不改写选择或偏好领域。更新活动皮肤时，窗口保留旧渲染直至提交完成并加载新的完整版本，再通过现有切换控制器挂载。发起操作的窗口立即刷新目录，其他窗口在重新聚焦或打开管理器时刷新。更新非活动皮肤时，当前已选皮肤和渲染保持原样。
- 旧偏好继续应用于相同的颜色和已声明效果。新版缺少的效果不参与渲染，已有偏好保留在 profile，回滚时重新可用。保存其他设置时可保留这些原值，Host 仍拒绝为未声明效果新增或修改偏好。随包偏好仍由用户显式采用。包变更后，旧详情页的草稿应重新加载，避免用旧包修订号覆盖新版设置。
- 新版与当前外观模式不符时沿用原生回退，保留已存选择。客户端加载或挂载出错时采用已有的安全回退并显示失败，保留本地回滚入口。更新和回滚的成功反馈以 Host 的提交和刷新后的包版本为依据。

## 验收夹具

同一皮肤 `test.skin.upload` 的 ZIP v1.0.0 与 v1.1.0 由 [版本夹具](../test/fixtures/package-versions.mjs) 中的 `packageVersionPair` 生成。第二版改用不同画布颜色并移除浮尘。两版各自通过生产导入与加载，普通导入在已安装时拒绝第二版，活动和非活动选择保持一致。

实现阶段用这对 ZIP 覆盖活动、非活动、偏好保留、回滚、同修订号并发和普通导入拒绝。对阶段写入、替换前后取消、响应丢失、进程中断与重启分别断言有效目录、选择、偏好及清理。两端真实验收至少验证活动更新、旧效果偏好在回滚时重新生效，以及更新非活动包时当前外观保持。
