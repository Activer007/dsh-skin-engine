## 当前主线的操作入口

| 操作 | 入口及行为 |
|---|---|
| 找皮肤、调皮肤特效、管理包 | 左侧「外观中心」，使用皮肤库、特效与性能、皮肤管理三页 |
| 修改参数 | 草稿在当前窗口跨导航保留；点击应用写入 Profile，插件卸载或窗口重启会清除未保存草稿 |
| 真实预览 | 点击「在聊天中预览」，返回原聊天，等聊天可见后开始约 30 秒的预览 |
| 取消或到期 | 点击聊天操作条的取消，或在「设置 → 皮肤引擎 → 紧急恢复」取消；到期恢复已保存外观。打开、关闭设置期间预览继续 |
| 应用 | 从外观中心或聊天操作条应用；收到修订冲突时复核当前保存值和草稿后重试 |
| 修改窗口特效 | 「设置 → 皮肤引擎 → 窗口效果」调整当前窗口的模式与质量。关闭窗口特效会保留已保存的皮肤和配色 |
| 故障恢复 | 在「设置 → 皮肤引擎」检查 Host 或二次确认恢复默认外观；恢复会清除已保存的皮肤选择，保留皮肤包和各皮肤偏好 |

包导入/更新期间可以离开外观中心；不要重复提交。取消后以 Host 回读为准，结果不确定应刷新核对，不能将取消提示当作服务端已撤销。草稿与已保存、当前渲染、临时预览是不同状态。

## 证据索引与门禁命令

模板 `docs/navigation-release-evidence.json` 已记录 NAV05 和 SYS01 合并提交，运行结果字段刻意留空；它不是已归档报告。历史候选与部分结果见本手册，补验后应另存实际索引，不以模板空值推断历史双端从未运行。复制模板到验收输出目录，使用相对于索引文件的证据路径（或仅供本地使用的绝对路径）。保留最终索引的可分享副本。

```sh
node --test test/navigation-release-gate.test.mjs
node scripts/acceptance/navigation-release-gate.mjs /path/to/navigation-release-evidence.json
```

CLI 检查两项依赖的已合并声明和提交格式、候选审查与双端记录的候选 SHA、包哈希、指定的验收宿主版本、八类观察记录及证据文件是否齐全。它还会读取共同候选包并计算 SHA-256。精确宿主版本仅用于本矩阵基线。pending、blocked、waived 和未解决的 exceptions 均阻止最终完成。

**限制：** 这是证据完整性校验器，不执行 UI、不证明文件内容真实，也不验证 Git 祖先关系。LHA 必须另用 `git merge-base --is-ancestor <依赖提交> <候选提交>` 核实依赖已纳入候选，亲自审阅证据，运行完整 `verify:local`。没有真实证据时不要修改模板以得到绿色结果。
