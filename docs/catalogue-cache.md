# 皮肤目录缓存与百包专项（NEXT-10）

## 读取与刷新

- 普通目录请求复用当前 DSH profile 的内存索引，5 秒后按需重新扫描。并发读取共享扫描。取消单个请求只结束该请求的等待。
- **Reload skins** 发出 `GET /api/dsh-skin-engine/skins?refresh=1`。直接在磁盘上增改本地包后，可用这个入口立即刷新。导入、更新、回滚和卸载成功后，处理写入的 Host 立即使其索引失效，横跨写入的扫描结果会被丢弃。同一 profile 内其他 Host 的索引按短期有效期重新读取。
- 预览沿用浏览器懒加载。预览请求通过包 revision、Manifest 和包路径校验后，才返回图像内容的 ETag 或 `304`。图像改变后会收到新内容。缺图占位图、非预览资源和错误响应仍使用 `no-store`。

## 复跑

用 [官方 DSH 验收命令](acceptance.md#运行)，把 `--suite catalogue-cache` 分别加到 Web 和 Windows Desktop 命令。把 `--archive` 指向通过 `npm pack` 构建的同一份候选 tarball。基线 Web 命令另加 `--catalogue-baseline`，并指向变更前的 tarball。Windows 实测使用 `--desktop-disable-occlusion`。

每轮在独立 profile 中放置 10 或 100 份本地 Manifest 和预览资源，另有 13 套内置皮肤。记录一次全量扫描及五次普通请求的时延。候选产物使用显式刷新测量全量扫描。记录首图可用时间、首图可用时与滚至最后一张时已发出请求的不同缩略图数量，以及图像条件请求的响应码。100 包轮的末图特意缺失，用于确认远端卡片按需发出请求并显示占位图。候选产物另通过设置页安装、更新、回滚并卸载一个真实 ZIP，以条件请求验证每一步的旧预览 URL 都已失效。
